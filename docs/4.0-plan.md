# 4.0 RC Companion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship KART 4.0 as raid tools plus an in-addon RCLootCouncil companion (nick-stable council + council award relay); remove the built-in loot council.

**Architecture:** `RCCompanion.lua` (`KART.RC`) loads from the existing `.toc` with `OptionalDeps: RCLootCouncil`. The raid leader's `rcCouncilMembers` string (nicks or names) is resolved through `KASC.Identity` and written into RC's `db.profile.council` GUID list. Council clients whisper `RC_AWARD` to the ML; the ML client `pcall`s `RCLootCouncilML:Award`. Built-in LC files and tests come out after the companion is green.

**Tech Stack:** WoW Lua 5.1 / LuaJIT, `KASC:Send` / `RegisterMessage`, `KASC.Identity`, RC AceAddon `RCLootCouncil` + `RCLootCouncilML`, existing `tests/wow_stubs.lua` + `luajit tests/run.lua`.

**Spec:** `docs/4.0-RC-COMPANION.md`

## Global Constraints

- Lua 5.1: no `goto`, `unpack` not `table.unpack`, no `//`.
- English comments and commit messages; `Locales/deDE.lua` values stay German.
- Companion is **not** a second addon. No `RCLootCouncil_KART.toc`.
- Do not reimplement session, Force-Win, TradeUI, history, WowUtils columns, or a lootmaster ≠ raid leader.
- RC APIs are called through `pcall`. A missing method is a no-op plus one print, never a load error.
- Changelog: one line per entry, bold lead + effect; update `CHANGELOG.md` then `CHANGELOG-de.md` in the same task that bumps the version.
- `docs/superpowers/` is gitignored; this plan and the spec live under `docs/` so they ship on the branch.

- [ ] **Step 3: Write minimal implementation**

Register in `RC.Enable`:

```lua
KASC:RegisterMessage("RC_AWARD", { payload = true, group = true, enabled = RC.IsRCLoaded },
    function(payload, ctx)
        RC.HandleAwardRequest(payload, ctx)
    end)
```

Payload format `session:winnerName:responseID` — `winnerName` may contain hyphens (realm). Parse with `payload:match("^(%d+):(.*):(%d+)$")` so the middle field may include `:`. If that is too fragile, use a single `-` delimiter only after the session number: `^(%d+):(.*)$` and treat the last `:`-suffix as responseID.

`RequestAward`: if `RCLootCouncil.isMasterLooter`, call `Award` locally and return. Else `KASC:Send("RC_AWARD:" .. ..., "WHISPER", mlName, { prio = "ALERT" })` where `mlName` is RC's master looter name (`addon.masterLooter` or `addon:GetML()` — `pcall`, fall back to `UnitName("player")` only if we are ML). If `KASC` reports restricted, print `KART.L.RC_AWARD_RESTRICTED` and return.

`HandleAwardRequest`: only if we are ML (`isMasterLooter`). Resolve sender via `Identity.ResolvePlayer(ctx.sender)`. Sender GUID must be in `db.profile.council` **or** in `RC.ResolvedCouncilGUIDs()`. Then `pcall(RCLootCouncilML.Award, RCLootCouncilML, session, winner, response)`.

Do **not** hook the voting-frame menu in this task (needs frames). Export `RC.RequestAward` so Task 4's hook is one call.
